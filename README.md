# Ground Handling System

АРМ диспетчера наземного обслуживания воздушных судов — настольное приложение
на Java 21 / JavaFX для планирования, координирования и контроля погрузки и
разгрузки самолётов в режиме, близком к реальному времени.

Приложение ведёт суточный план рейсов (информационное табло), управляет
загрузкой грузовых отсеков с двухуровневым контролем грузоподъёмности
с учётом веса пассажиров и экипажа, распределяет технику и бригады перрона
и выгружает отчёты в CSV.

## Возможности

- **Табло рейсов** — суточный план с цветовой индикацией статусов
  (SCHEDULED, ARRIVED, LOADING, BOARDING, READY, DEPARTED, DELAYED),
  виджетами статистики («Всего рейсов», «Активных», «Завершено»)
  и журналом событий с метками времени.
- **Управление грузом** — погрузка и разгрузка по отсекам с двухуровневой
  проверкой: лимит конкретного отсека → суммарная полезная нагрузка борта
  с учётом веса пассажиров и экипажа. Перегруз блокируется на уровне
  бизнес-логики, а не интерфейса.
- **Учёт веса пассажиров** — отдельное поле в панели деталей рейса;
  общая грузоподъёмность считается как груз + пассажиры + новый груз.
- **Парк ВС** — регистрация бортов (Boeing 737, Airbus A320) с автоматическим
  созданием грузовых отсеков по спецификации типа и валидацией формата
  и уникальности бортового номера.
- **Ресурсы перрона** — учёт техники и бригад, ручное назначение через
  выпадающие списки (занятые ресурсы помечены «(Занят)») и автоматическое
  распределение свободных ресурсов кнопкой «Авто-распределение».
- **Жизненный цикл рейса** — смена статуса через выпадающий список в панели
  деталей с контролем допустимых переходов; рейсы в статусе DEPARTED закрыты
  для погрузки и назначения ресурсов.
- **Экспорт отчёта** — кнопка «Экспорт CSV» в левой панели навигации:
  перечень рейсов с восемью колонками, файл «рейсы_ГГГГ-ММ-ДД.csv»
  в кодировке UTF-8 с BOM (корректно открывается в Microsoft Excel
  и LibreOffice Calc, повторные выгрузки не перезаписывают предыдущие).
- **Автообновление** — опрос базы данных каждые 5 секунд через JavaFX
  Timeline; опрос приостанавливается при открытой панели деталей рейса,
  чтобы не прерывать работу диспетчера.

## Архитектура

Многослойная архитектура (Layered Architecture) с элементами MVC.
Корневой пакет — `com.kuleshov.groundhandling`.

```
com.kuleshov.groundhandling
├── domain        # сущности JPA и перечисления (Flight, Aircraft, Cargo, Resource…)
├── repository    # доступ к данным, паттерн Репозиторий, JOIN FETCH против LazyInitializationException
├── service       # бизнес-логика: контроль веса, распределение ресурсов, валидация рейсов
├── controller    # контроллеры JavaFX (FXML-разметка в src/main/resources)
├── HibernateUtil # фабрика сессий (Singleton)
└── MainApp       # точка входа
```

Ключевые компоненты:

- `WeightBalanceService` — двухуровневая проверка грузоподъёмности
  (`validateAndAddCargo`, `unloadLastCargo`);
- `ResourceAllocationService` — автоматическое распределение свободной
  техники и бригад (`allocateResources`);
- `OperationResult` — паттерн Result Object для единообразной обработки
  результатов операций сервисного слоя;
- `CSVExporter` — потоковая запись отчёта с экранированием значений.

## Запуск

### Предварительные требования

- JDK 21+
- Maven 3.8+
- Docker 20.10+ с Compose

### 1. База данных

Проект использует PostgreSQL 16 в контейнере Docker. В корне проекта:

```bash
docker compose up -d
```

Контейнер поднимает СУБД с маппингом портов **5433:5432**, именованным томом
для данных, инициализационным скриптом `init.sql` и healthcheck-ом на основе
`pg_isready`. Проверить состояние:

```bash
docker compose ps
```

### 2. Приложение

Откройте проект в IntelliJ IDEA и выполните цель Maven:

```
Lifecycle → javafx:run
```

или из терминала:

```bash
mvn javafx:run
```

После компиляции откроется главное окно
«Ground Handling System – Панель управления».

### 3. Конфигурация Hibernate

Параметры подключения задаются в `hibernate.cfg.xml`: подключение к
PostgreSQL на порту 5433, стратегия схемы `hbm2ddl.auto=validate`
(схему создаёт `init.sql`), пул соединений HikariCP
(максимум 10, минимум 2, таймаут 5000 мс). Пароль базы данных указывается
в конфигурации — для публичного репозитория держите его в переменной
окружения или файле `.env`, не коммитьте реальные креды.

## Тестирование

25 интеграционных тестов (JUnit 5) в трёх классах:

| Тестовый класс | Сценариев | Что проверяет |
|---|---|---|
| `FlightManagementServiceTest` | 12 | валидация создания рейса, вес пассажиров, блокировка DEPARTED |
| `WeightBalanceServiceTest` | 6 | двухуровневый контроль грузоподъёмности на реальных спецификациях |
| `ResourceManagementServiceTest` | 7 | учёт техники и бригад, освобождение и удаление ресурсов |

Тесты выполняются на встраиваемой СУБД H2 в оперативной памяти — запущенный
контейнер PostgreSQL **не требуется**:

```bash
mvn clean test
```

Конфигурация Hibernate для тестов вынесена в `hibernate-test.cfg.xml`
(`hbm2ddl.auto=create-drop`). Выбор файла конфигурации переключается
системным свойством `hibernate.cfg`: базовый класс `IntegrationTestBase`
вызывает `System.setProperty("hibernate.cfg", …)` до инициализации фабрики
сессий, поэтому одна сборка работает и с PostgreSQL, и с H2. Перед каждым
сценарием таблицы очищаются в порядке, обратном внешним ключам, — тесты
независимы друг от друга.

## Формат экспорта CSV

Отчёт содержит восемь колонок: номер рейса, бортовой номер, тип воздушного
судна, статус, плановое время вылета, вес пассажиров, вес груза, общий вес.
Файл пишется в кодировке UTF-8 с BOM-маркером, значения экранируются на
случай символа-разделителя «;», имя формируется с датой выгрузки
(`рейсы_ГГГГ-ММ-ДД.csv`).
